## Context

Prospero is a news aggregator built as a Bachelor's thesis at HSE — the brief was open-ended (build something real), so the scope became a decision exercise as much as an engineering one: what fits in a month, sized like a real product, without ending up as a toy.

## What was built

A four-part system: a public frontend, a Go API, an admin panel, and the observability stack tying them together.

- **RSS harvesting** — a `gocron`-scheduled job pulls new articles from each registered source on an interval and indexes them.
- **Search** — ElasticSearch holds article content and a denormalized publisher index for autocomplete; PostgreSQL is the source of truth for publishers and their RSS sources, including geo-coordinates for the map.
- **Frontend** — Next.js/React with Redux Toolkit and RTK Query, Mantine UI, and a Yandex Maps view of results. Filters combine a date histogram, category/country/language dropdowns (including a clickable world map), and boolean query operators (AND / EXACT / NOT).
- **Admin panel** — a separate Next.js app, JWT-authenticated, for adding and editing publishers and RSS sources.

## Technical decisions

**Why Go, untested by him at the time?** The scheduler and HTTP layer needed to be simple and fast to write correctly under a one-month budget — Go's standard library and static typing caught a lot of mistakes at compile time that a scripting language wouldn't have.

**Why split search into ElasticSearch and PostgreSQL instead of one database?** Postgres is the right shape for the small, relational catalog of publishers and sources. ElasticSearch is the right shape for full-text search and autocomplete over harvested article content — using Postgres for both would have meant hand-rolling fuzzy text search on top of it.

**Why a separate admin app instead of an admin mode in the main frontend?** Different audience, different auth model — the public site is fully open, the admin panel is JWT-gated. Keeping them as separate Next.js deployments meant the public site's bundle never had to carry admin-only code.

## Observability

Logs in the ELK stack, request tracing in Jaeger, metrics in Prometheus/Grafana, and Yandex.Metrica for traffic — set up alongside the first backend endpoints rather than added later. CI/CD on a self-hosted GitHub Actions runner rebuilds and redeploys the Docker Compose stack on every push to main.
