## Kontext

Der Infineon-Campus in Dresden hat Hunderte Parkplätze über mehrere Bereiche verteilt. Vor diesem Projekt holte das Unternehmen Angebote von kommerziellen Parkleitsystem-Anbietern ein — das beste Angebot lag bei **480.000 €/Jahr** an Lizenz- und Wartungsgebühren.

Die Alternative: Eigenentwicklung.

## Was gebaut wurde

Ein vollständiges Parkleitsystem, von der Hardware bis zum Dashboard:

- **Eingebettete Firmware** in C auf IP-Kameras — führt ANPR (automatische Kennzeichenerkennung) und Belegungszählung durch, ohne Videostreams über das Netzwerk zu senden.
- **Python-Computer-Vision-Service** verarbeitet die Kameradaten und bestimmt, welche Parkplätze belegt sind, um sie auf der Karte hervorzuheben.
- **C#-Geräteverwaltungsschicht** übernimmt die Authentifizierung, stellt die REST-/WebSocket-API bereit und kümmert sich um Kamera-Provisionierung, Firmware-Updates und Health-Monitoring.
- **React + TypeScript Dashboard** gibt Sicherheitspersonal und Fahrern eine Echtzeit-Karte der verfügbaren Plätze.

</ModeAware>

## Architektur

```
                   MQTT
┌────────────────┐       ┌─────────────────────┐
│ IP-Kamera (C)  │─────► │ Backend (C#)        │
│ ANPR + Zählung │       │ REST-/WebSocket-API │
└────────────────┘       └─────────────────────┘
                                    │ WebSocket
                                    ▼
                          ┌──────────────────┐
                          │ React-Dashboard  │
                          │ (Echtzeit-Karte) │
                          └──────────────────┘
```

Die Kameras führen die Erkennung lokal aus (Edge Computing) — nur Belegungsereignisse werden über das Netzwerk gesendet, kein Video. Das hält die Bandbreite niedrig und vermeidet DSGVO-Probleme durch zentrale Videospeicherung.

</ModeAware>

## Herausforderungen

**Die embedded + Web Brücke.** C für ressourcenbeschränkte Kameras zu schreiben und das dann an eine React-SPA anzubinden, erforderte eine saubere Protokollgrenze. MQTT wurde statt HTTP-Polling gewählt, um die Latenz unter 500 ms zu halten.

**Graceful Degradation.** Fällt eine Kamera aus, zeigt das System keine veralteten Daten an — die Zone wird als „unbekannt" markiert, und das Dashboard spiegelt Unsicherheit wider, statt zu lügen.

**Mandantenfähige Konfiguration.** Verschiedene Parkplätze haben unterschiedliche Layouts. Ein Configuration-as-Data-Ansatz bedeutet, dass ein neuer Parkplatz eine JSON-Datei ist, keine Codeänderung.

## Ergebnis

Das System ging auf dem Campus live. **480.000 €/Jahr gespart** gegenüber dem Anbieterangebot. Das eigenständig hinzugefügte Schrankensteuerungs-Subsystem bedient **8.000 registrierte Nutzer** mit **3.000 monatlich aktiv**.
