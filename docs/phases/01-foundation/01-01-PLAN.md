<objective>
Bootstrap the Next.js 16 App Router project and establish the next-intl localized routing skeleton so a visitor can reach /en/, /de/, and /ru/ and see localized UI strings on a statically prerendered home page.

This is the first vertical slice of the Walking Skeleton: it stands up the full request path (middleware → locale layout → page → localized message) end-to-end with the `setRequestLocale` static-rendering convention baked in from the first commit. It deliberately establishes the load-bearing conventions (plugin order, middleware matcher, setRequestLocale, cyrillic font subset) that every later phase depends on.

Purpose: Get the technical spine correct on day one — the most expensive mistakes (dynamic-rendering inflation, broken middleware matcher, missing locale dimension) are unfixable retrofits.
Output: A bootstrapped, deployable project where /en/, /de/, /ru/ each render a localized prerendered home page.
</objective>
